# Deploy to Main (Vercel trigger)

This skill handles the recurring pattern in this repo:
- Work happens on a feature branch (`claude/claude-md-DXmYK` or similar)
- Vercel deploys from `main` only
- Merging often produces conflicts because `main` moves independently

## Steps

### 1. Capture state
```bash
FEATURE=$(git branch --show-current)
git log --oneline -3
git log origin/main..HEAD --oneline | wc -l   # how many commits ahead
```

If already on `main` with no unpushed commits, just push:
```bash
git push origin main
```

### 2. Pull latest main and merge
```bash
git checkout main
git pull origin main
git merge "$FEATURE" --no-ff -m "Merge $FEATURE into main"
```

### 3. If conflicts arise

Check which files are conflicted:
```bash
git diff --name-only --diff-filter=U
```

**Resolution strategy for this repo:**
- **Import lines** (e.g. adding `useRef`): keep the union — include all imports from both sides.
- **New hooks / refs** (e.g. `autoGeneratedPlanRef`): keep the feature branch addition.
- **Logic additions** (e.g. `workingDiagnosis?.diseaseId` fallback): keep the feature branch version when it's additive/defensive.
- **When in doubt**: keep both sides — the feature branch adds things, main may reorganise. Read the surrounding context before discarding either side.

After resolving each file:
```bash
git add <file>
```

Confirm no markers remain:
```bash
git diff --check
```

### 4. Typecheck — must pass before pushing
```bash
pnpm run typecheck
```

If typecheck fails, fix the errors (they are usually caused by the conflict resolution) and re-stage.

### 5. Commit the merge and push
```bash
git commit -m "Merge $FEATURE into main"
git push origin main
```

### 6. Return to feature branch
```bash
git checkout "$FEATURE"
```

### 7. Tell the user
> Pushed to `main` — Vercel will rebuild in ~1–2 minutes. Hard-refresh (`Cmd+Shift+R` / close and reopen the tab on iPad) once the deploy finishes.

## Notes
- Never force-push main.
- Never skip `pnpm run typecheck` before pushing to main.
- The feature branch (`claude/claude-md-DXmYK`) is the development branch; all new work commits go there first, then merge to main for deploy.
- If the merge produces a large conflict in a single file, read the whole conflict region before resolving — the feature branch additions are almost always *additive* (new state, new UI elements) and should be preserved alongside whatever main changed.
